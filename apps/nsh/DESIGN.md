# Mobile UI standards

Targets: native iOS and Android; headless is a behavior harness. Preserve the existing dark cyan/blue circular-eye face and minimal conversation surface. The face occupies the main view; connection settings, writing, replies and agent decisions use temporary dialogs. No LAB or secondary navigation is introduced.

All presentation colors live in `theme.json`. Cyan belongs to the face and primary conversation action, coral to stop/failure, muted foreground to honest disconnected states. Never show a connected microphone, model or base without evidence. Do not synthesize audio amplitudes.

`ui/Controls.tsx` owns styled NSH base Button/Input/Dialog behavior: minimum 48-point targets, focus/disabled/press states, bounded scrolling and a reachable close action. Dialogs follow keyboard height. Connection fields use two columns in a wide viewport and one in portrait. Long replies have a full selectable, scrollable view; face captions remain summaries.

Approval always identifies the operation and its parameters. File overwrite approval includes the exact proposed content. Remember and forget must be visually distinct. Allow-once references are generated by the current UI press and bound to that session.

One native Canvas draws the face texture, radial eye gradients, brows and mouth in the original 620 × 340 coordinate system. Scale eye radius uniformly; never squash circles into ellipses. Breathing runs natively; reduce-motion and background lifecycle stop it. Blink timers belong to the face owner and are disposed. Audio waveform data will come from actual capture/playback when the media adapter is connected.

Review actual native screenshots as well as headless behavior. iOS landscape and Android portrait have been checked; thermal behavior, real sensors and hardware latency need their own evidence.
