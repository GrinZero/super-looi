# 语音配置与同页调试台

## 页面目标

沿用图二的「服务卡片 → 对应配置 → 底部会话栏」结构。用户可以在语音页完成连接配置、调整音色、试听和麦克风对话；开始对话后原地显示连接、聆听、回复与结束状态。

核心操作顺序：选择服务 → 配置凭证 → 调整或试听音色 → 保存音色 → 在当前页对话 → 根据听感继续调整。

## 页面布局

```text
实时语音

语音服务
┌ 豆包 · 已配置 · 当前选择 ┐  ┌ OpenAI Realtime · 待接入 ┐

豆包
连接凭证                         音色
已配置   [连接设置…]             [默认音色 / 自定义…]  [试听]
                                自定义 Speaker ID（按需展开）
                                [保存音色]（有改动时出现）

对话调试
你：最近一次识别内容
LOOI：最近一次回复

Hey LOOI 自动唤醒 [开关]
───────────────────────────────────────────────────────
待机 / 连接中 / 正在聆听 / 正在回复          [开始对话]
```

- 横屏沿用 80pt 导航轨与现有顶栏。服务卡片采用紧凑横排；顶栏只保留页面标题和返回，避免再重复一组服务胶囊。
- 对应配置区内用分组和细分隔线组织凭证、音色。音色属于高频调试项，选择与试听直接可见。连接凭证默认摘要，按需编辑。
- 「对话调试」区域使用剩余高度，显示当前轮用户转写与回复，各自标明说话方；长内容在该区域滚动。连接失败直接在状态附近说明原因。
- 底部操作栏固定在工作区内；开始后替换为结束对话、静音／取消静音，正在播报时提供打断。状态与主操作不随转写滚走。
- 唤醒开关放在服务配置外，表达其为全局偏好；试听期间的暂停由状态文案表达，开关仍保留用户原值。
- 844 × 390pt 横屏预算：顶栏 48pt、服务区约 68pt、配置摘要约 88pt、底部控制约 52pt，剩余区域分配给转写与间距。44pt 热区优先，详情展开时让配置与转写共用工作区滚动，底栏保留。
- 竖屏服务卡片可改为两行；配置、音色、转写顺序不变，底部会话控制保持可达。编辑凭证或 Speaker ID 时，输入与保存随键盘避让。
- 使用现有明暗主题、系统字体及 `ActionButton`、`TextField`、`SwitchRow`；服务卡片的选择和待接入状态同时使用形状／文字表达。

## 服务管理的归属

推荐将语音服务管理收在语音页，用户看到服务、选中服务、编辑连接和调试始终围绕同一个对象。

| 方式 | 具体用途 | 复杂性成本 | 选择 |
| --- | --- | --- | --- |
| 页内服务卡片 + 对应连接编辑 | 在豆包和 OpenAI Realtime 之间选用，并在原地调试 | 增加服务选择和独立配置快照，入口与页面上下文一致 | 采用 |
| 全局统一服务中心 | 同时管理文本模型、语音与家居的连接 | 增加跨模块导航、能力分类、账号与凭证关系；当前调试需要来回切页 | 当前需求收益不足 |
| 每家服务允许添加多个连接 | 同一服务使用多个账号、网关或项目 | 增加连接 ID、默认连接、重命名与删除、会话绑定 | 等出现同服务多账号需求再设计 |

### 卡片与连接设置

- 卡片表示服务选择，不表示连接成功；`已配置`仅说明凭证存在，`已连接`仅出现在实际会话状态中。
- 当前版本豆包可配置；OpenAI Realtime 显示「待接入」且不触发选择或连接。
- 点击「连接设置…」在对应配置区内展开短表单，内容为 API Key 与保存／取消。已保存的 Key 不回填，空输入不执行保存；保存后回到摘要。点击卡片本身负责选择，避免在卡片内部嵌套多组操作。
- 运行中更换 Key 会结束当前连接：提交按钮对应标为「保存并结束对话」或「保存并停止试听」，空闲时为「保存」。保存成功后回到待机，由用户再次开始；保存失败保留输入和当前连接。
- 后续开放 OpenAI 时，卡片可选；未配置的服务选中后直接显示对应连接编辑，调试动作显示「先配置凭证」。服务选择同时决定后续首页语音和自动唤醒使用的服务。
- 若沿用已有文本模型的 API Key，摘要明确显示「使用模型页的 OpenAI 凭证」；填写语音专用 Key 后由语音配置覆盖。保持现有凭证解析规则，不建立第二个全局凭证中心。
- 自定义地址与模型设置只有在确有网关／模型选择需求时进入该服务的连接详情。当前环境变量只作为启动配置来源，不把它们生成为所有服务的通用表单。

## 音色调试

### 选择、试听与保存

- 豆包先呈现真实的默认音色，以及自定义 Speaker ID 输入入口。没有经过协议与账号验证的音色不作为推荐列表展示。
- 「试听」使用当前草稿；不要求先保存，也不修改首页与下次会话的默认音色。
- 试听使用固定短句，例如「你好，我是 LOOI。我们可以开始聊天了。」同一短句方便比较声线。按钮在生成／播放时显示相应状态，可停止；错误靠近试听操作展示。
- 试听只建立一次短输出会话，结束后关闭连接；不采集麦克风、不接收唤醒、不携带家居／底座／Agent 工具和后台任务播报。它验证当前服务与音色的真实输出能力。
- 播放结束以音频实际排空为准；手动停止立即清理待播音频。唤醒偏好为开、麦克风权限已授予且当前页面仍允许待机时，恢复唤醒；试听结束不触发新的麦克风授权请求。
- 保存音色将草稿写入对应服务的配置；首次或空闲时，下一次对话使用新音色。恢复默认属于同一编辑流程。

### 对话过程中调整音色

目前音色在新会话握手时传入；OpenAI 适配器还固定输出音色，因此首版采用一致且可实现的「重连应用」语义。

- 对话中允许编辑并保存；显示「已保存，下次对话生效」，同时显示当前会话实际使用的音色。
- 已保存音色与会话音色不同时，提供「应用并重连」；点击后结束当前会话并用保存的配置重连，仍停留在当前页。未保存草稿使用「试听」「保存音色」；不让应用操作隐式保存草稿。重新建连就是新的协议会话，界面保留上一轮调试文字，随后显示新一轮结果。
- 对话中点击试听，操作明确命名为「结束并试听」；用户一次点击即结束对话并试听草稿，完成后回到调试待机。随后可以用「开始对话」测试真实麦克风交互。
- 唤醒、试听与对话共享现有音频通道，由运行时串行接管；页面不另开独立音频播放器争用输出。

## 服务切换与生命周期

- 空闲时切换服务：保存选择、显示该服务自己的凭证与音色，并将后续唤醒绑定到该服务。
- 对话或试听中，另一张可用服务卡片直接标出「结束并切换」或「停止试听并切换」；点击即停止当前活动，选用目标服务并显示其配置，回到待机。用户配置完成后，在底栏开始新的对话；切换卡片本身不自动建立对话。
- 服务卡片、配置区与调试栏始终指向同一个选用服务。保留当前会话启动时的音色快照，用于表达「保存后下次生效」；不增加独立的跨服务查看状态。
- 从语音页开始的会话属于同一个 `VoiceRuntime`。显式返回桌宠页可保留普通对话；从语音页切入其他管理模块时结束调试对话。现有离页逻辑只停止唤醒待机，需要补上这条退出处理。进入后台／登录流程沿用现有释放音频的行为。
- 试听属于语音页短任务；离开语音页即停止。唤醒偏好不因试听临时暂停而被写成关闭。
- 权限请求沿用现有麦克风链路，授权后在当前页重试。试听不请求麦克风权限。
- 试听结束不能直接复用当前 `endSession()` 的无条件唤醒恢复分支；运行时恢复和 `store` 的自动待机 effect（响应式副作用）需共同使用上述权限／页面条件。用户明确开始对话或开启唤醒时才进入相应授权流程。

## 当前代码事实与实现边界

现有 `store.startVoice()` 直接调用 `VoiceRuntime.start()`，没有页面跳转；`VoiceSpaceView` 已包含开始／结束、静音、打断和单段回复。主要增量为图二布局、真实的用户转写、音色试听、运行中应用配置，以及后续服务选择。

现有服务选择来自 `VOICE_PROVIDER`，`VoiceRuntime.protocol` 在构造时固定；`VoiceCredentialStore` 已按服务保存 Key，但音色只有豆包单值。OpenAI 的协议适配和用例已存在，当前握手仍硬编码音色，真实接入和页面服务切换需要继续完成。

### 状态与职责

| 位置 | 持有的状态与动作 |
| --- | --- |
| `VoiceSpaceView` | 查看哪个服务、展开哪个连接表单、音色草稿、局部输入错误；不直接操作 WebSocket 或原生音频 |
| `store` | 暴露页面需要的配置摘要、运行状态及操作；协调页面离开，不重复会话状态机 |
| `VoiceCredentialStore` | 每服务的 Key、保存音色与默认服务，保留全局唤醒偏好和现有凭证来源规则 |
| `VoiceRuntime` | 单一音频通道、普通对话／试听的切换、应用重连、实际会话配置、试听结束与待机恢复 |
| `LiveVoiceSession` 与协议适配器 | 单次连接、握手、文本发音请求、音频收发、转写与终止；服务差异集中在适配器 |

### 接口方向

以下签名用于说明调用关系，名称在实现时与现有命名对齐：

```ts
// 草稿来自页面；Runtime 负责串行停止旧连接与建立试听。
await voice.preview({ providerId, voiceId: draftVoiceId });

// 保存与应用分开：保存不改变进行中的协议会话。
voice.configureVoiceId(providerId, draftVoiceId);
await voice.restartWithConfiguration({ providerId });

// 停止当前试听或会话统一经由运行时。
voice.endSession();
```

- 扩展现有 `LiveVoiceSession` 增加 `purpose: "conversation" | "preview"`；试听只开启输出与单次文本请求，真实麦克风对话继续沿用原有路径。复用连接、解码与播放生命周期，避免复制一套试听运行时。
- 试听握手使用空工具集，按各协议支持的字段关闭输入／自动轮次，由适配器封装差异；收到 `session_ready` 后只发送一次试听文本，不执行 `setCaptureMode("conversation")` 或播放就绪提示。`tick()` 只推进待播音频，不发送捕获帧或静音补帧；服务响应完成且 PCM 排空即结束，不进入 `listening` 或 12 秒静默等待。服务协议是否允许该输出流程，是豆包及后续 OpenAI 各自接入时的联调项。
- 为现有协议适配器增加明确的试听文本请求；不借用后台任务通知的提示语协议，避免模型将试听短句转述成任务回执。试听语义是请求朗读指定短句；服务实际是否逐字输出须在定向联调核对。
- 会话状态补充当前 `purpose`、实际使用的服务与音色，以及最近一轮用户转写；配置快照保留已保存值。用户转写来自已有的规范化协议事件，当前回复继续使用现有回复事件。
- 服务切换由运行时重建协议适配器，保留同一个运行时及任务桥接所有者。页面调用一次切换操作，不理解停止待机、清播放和建连顺序。
- 持久化配置增加 `selectedProviderId` 与按服务组织的音色配置。既有 `voiceId` 迁为豆包音色；未保存服务选择时沿用 `VOICE_PROVIDER`，再以豆包为默认。原 `apiKeys` 和唤醒偏好继续复用。
- 当前 `VOICE_BASE_URL`／`VOICE_MODEL` 只适用于启动环境指定的服务，不能在界面切换后流入另一服务。未配置覆盖值的服务使用自己的协议默认值。
- 固定两项服务描述即可驱动卡片和音色能力。不引入插件注册表、通用连接实体、独立调试数据库或新依赖。

### 关键取舍

`VoiceRuntime` 继续使用 class（类）：它持有音频、会话、定时器与待机的长期生命周期，新增试听与切换属于同一所有者的操作。把试听做成独立类会增加两个音频所有者之间的协调。

协议编码继续采用现有函数与适配器；页面维持已有信号和组合式组件。仅有布局复用时使用页内函数，出现第二个真实调用方再提取共享组件。若后续纯 TTS（文本转语音）通道成为明确产品需求，再比较与当前短 Realtime 会话试听的成本及听感差异。
