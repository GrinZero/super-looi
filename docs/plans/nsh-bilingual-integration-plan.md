# NSH 中英双语接入实施计划

依据：[中英双语接入调研](../nsh-multilingual-integration-research.md)。首批支持简体中文与英语；默认跟随系统，可在应用内覆盖。词条保存在仓库内，暂不接入 TMS。

## Step 1：建立界面语言状态与词条

- [x] 引入 i18next core 和 NSH 缺失的 `Intl.Locale`、`Intl.PluralRules` polyfill，仅载入 `zh`、`en` 规则；记录新增依赖的 bundle 增量。
- [x] 在现有 store 保存 `system`／`zh-CN`／`en-US` 偏好，系统模式订阅 NSH 响应式 `locale()`；提供一个最终界面语言读取入口。
- [x] 用本地中英词条和应用层翻译函数覆盖首页及语言设置，显式设置 `fallbackLng: "zh-CN"`；日期、数字显式传入最终语言。
- [x] 在 NSH 测试环境验证系统语言变化、手动覆盖及重启恢复、英文单复数与两种语言的日期格式。

## Step 2：迁移所有面向用户的界面文案

- [x] 迁移 NSH TSX 中的标题、按钮、状态、空态、Toast 和无障碍名称；英语按界面长度与语境写完整文案。
- [x] 将 runtime 传给界面的状态和错误改为稳定消息标识与参数，由应用层翻译；保持业务协议值和用户数据原样。
- [x] 在 iOS 模拟器逐屏检查首页、模型、语音、家居与任务空间的英文长度、即时切换和无障碍名称。

## Step 3：统一文字与语音对话语言

- [x] 新会话默认使用最终界面语言；用户明确指定语言或用另一语言提出完整问题时切换该轮回复；简短语气词沿用会话语言。
- [x] 更新 Realtime 提示词、文字 Agent 最终回答和记忆提示中的固定中文规则；生成时间按会话语言格式化。
- [x] 分别验证中文、英文和中英切换的文字与语音请求，核对转写、字幕、Agent 最终回答及回复语音。Pi voice 模式及 Realtime 同会话短回应语言保持与中文切换均已实测。
- [x] 保留已实测有英文文本与音频的默认 Vivi 音色。只有英文专用音色在当前模型与账号下取得真实音频帧后，才将其加入可选项。

## 完成标准

界面跟随系统语言且手动覆盖可持久化；两种语言的复数和日期正确；主要界面英文无截断；文字与语音对话按同一语言规则回复，字幕和最终回答一致。
