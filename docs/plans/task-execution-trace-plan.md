# 任务真实链路与本地 Trace

任务详情需要回答：模型看到了什么、调用了什么、工具返回了什么、最后回答是什么。原有 `steps` 仅保存状态摘要，不能承担执行证据的数据源。

## 记录边界

- 扩展现有 observation 记录器，开始和完成时向本地存储发送同一 span 的快照，Langfuse 继续导出同一 trace/span ID。未配置远程服务时仍记录本地数据。
- SQLite 按 span 保存记录，任务只保存根节点引用。这样语音会话、委派调用、后台任务和交付能够共享父子关系，不把整段语音会话复制到每个任务快照。
- 模型节点保存 Pi 实际请求上下文、模型及输出；任务节点保存恢复历史的消息数与会话归属。搜索节点保存服务端提供的搜索动作；服务端未公开的搜索正文不标成已取得。
- 工具节点记录真实参数、输出、错误与耗时；审批／提问及用户回应作为独立交互节点。语音连接记录现有转写、工具委派和结果通知。

## 界面

沿用主题的 background/card/muted/foreground/border/verified/destructive，正文使用平台字体，标识与耗时使用等宽字体。左栏是紧凑任务选择，右栏按调用关系展示执行树；模型输入、工具回执和原始数据按需展开。任务结果有独立标题，不混入工具输出。层级缩进只表达真实父子关系，每行 key 使用 span ID。

主操作是选择任务、展开节点和查看输入／输出，均可通过触控与键盘操作；滚动分别归列表和详情面板所有。使用现有 NSH 基础控件和主题，不增加 UI 或 tracing 依赖。

## 成本与取舍

增加一个 SQLite observation 表和结构化记录类型，用于独立保存长生命周期链路；相比在任务里复制历史和语音数据，减少重复存储与归属歧义。保留现有 tracer 接口与 Langfuse 属性键，避免两套插桩逻辑。UI 的解析函数负责显示语义，记录器不推断模型的证据来源。旧任务只展示已有步骤，并明确未保存输入／输出。

## 验证

以“前轮询问时间，后轮追问并额外搜索”为回归场景：能看到前轮消息确实在模型输入中，搜索动作独立存在，最终回答独立存在。覆盖本地记录不依赖 Langfuse、跨重启读取、同名多工具、失败／取消和语音父子链。执行类型检查和原生 UI 编译；设备验收仅使用开发真机横屏。
