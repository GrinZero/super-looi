# 智能家居空间（HomeSpaceView）交互、视觉与状态同步深度重构方案（V2）

## 1. 背景与核心痛点

基于用户在真实家庭环境（45 台米家/HA 设备）下的体验反馈，当前智能家居页面存在四类核心问题：

1. **功能性缺失与无意义原始数字（如扫地机器人显示 `13`）**
   - **现状**：点击监控、扫地机器人、电饭煲、洗衣机、空调等复杂设备，仅弹出一个底部通用小浮层（Inspector Sheet），缺乏专属的完整控制界面与核心遥测信息。
   - **原始数字根因**：
     - 在 `direct_miot` 模式下，`parseMiotSpec` 忽略了 MIoT 属性的 `value-list` 枚举映射与 `actions`，且 `mapMiotDevice` 将所有可读数值属性（含 `status`、`mode`、`work-mode` 等枚举状态码）直接映射为原始数字传感器（例如 `xiaomi.vacuum.d103cn` 的状态码 `13` / `14`）。
     - 在 `packages/home-devices/src/device-aggregator.ts` 的 `buildCycleTaskCapability` 中，`statusSensor` 正则 `/status|状态/` 误匹配了 `waterbox_status`（`"Yes"`）或原始数值状态码（`"13"` / `"14"`），并将其直接作为卡片大字号 `stageLabel`、`statusBadge` 与副标题展示。
     - 在 `external_ha` 快照中，部分温度传感器单位为华氏度（`°F`，如 `75°F`、`77.54°F`、`120.2°F`），聚合器未换算为摄氏度就直接拼接 `°C`；部分诊断传感器（如 `* 机器状态 室外管温`、插座芯片 `0°C`、人体存在传感器的 `config` 指示灯）干扰了设备分类与遥测提取。
2. **布局交互生硬（点击卡片进详情选 `1×1` / `2×1` / `2×2`）**
   - **现状**：点击卡片弹出的面板中包含 `1×1`、`2×1`、`2×2` 尺寸切换按钮，把“使用设备”与“编辑桌面布局”混为一谈。
   - **目标**：移除详情页内的尺寸选择器；支持**长按任意设备方块（`onLongPress`）直接进入自由布局编辑模式**，在网格上直接调整每个方块的尺寸（`1×1`、`2×1`、`2×2`）与自由移动/交换位置（上移、下移、左移、右移或点选交换目标格），将每个方块放到合适的位置。
3. **视觉过度依赖文字，缺少图形化 Icon**
   - **现状**：卡片与控制按钮通篇使用文字（如每个卡片右上角都是文字“开启”/“关闭”按钮），视觉单调且不利于多语言排版。
   - **目标**：构建基于 NSH `Canvas` / 几何矢量的语义化图标组件体系（`HomeIcons.tsx`），覆盖全部 23 类家电图标（监控、扫地机、电饭煲、洗衣机、空调、风扇、净化器、除湿机、电水壶、电热毯、灯光、多键开关、插座、电视、音箱、喂食器、门锁、传感器、路由器等）与核心操作图标（电源 `⏻`、播放/开始、暂停、停止、回充、集尘、洗拖布、烘干、加减、返回、尺寸与方向移动等）。
4. **开关按钮状态语义反直觉 + 外部渠道开关后状态不更新**
   - **问题 4a（按钮文案歧义）**：当“电脑”处于开启状态时，卡片右上角按钮显示文字“开启”，用户误以为点击是“执行开启”而非“关闭”。改为**圆形电源图标按钮（`⏻`）**，通过高对比度点亮态（`bg-primary text-primary-foreground`）与熄灭态（`bg-muted text-muted-foreground`）表达通断，同时在卡片副标题明确显示当前状态（如 `供电中` / `已开启` / `已关闭`）。
   - **问题 4b（大厅灯外部打开后不更新）**：
     - **实体误匹配根因**：`大厅灯`（`yutai.plug.fsov7m`）包含 3 个 switch 实体，其中排第一的是 `switch.*_disable_p_7_2`（`* 辅助开关 语音功能禁用开关`）。`findPrimaryPowerEntity` 未排除 `*` 辅助/禁用配置项，也未优先匹配 `supported_features.includes("turn_on")` 的主开关 `on_p_2_1`（`禹泰电工智能插座（Mesh） 开关`），导致大厅灯卡片一直绑定在“语音禁用开关”上！同理，`阳台灯`/`卧室灯` 的 `开关 按键` 未纳入 `PRIMARY_POWER_SWITCH_NAMES`。
     - **缺少实时轮询根因**：`store.ts` 在打开智能家居空间（`activeSpace === "home"`）期间没有任何定时状态同步机制，且顶部刷新按钮调用了全量重连而非轻量状态同步。

## 2. 模块边界与架构设计（遵循 `codebase-design` 深模块原则）

1. **协议与映射层（`@super-looi/home-assistant`）**
   - 扩充 `miot-spec-resolver.ts` 与 `miot-entity-mapper.ts`：解析 `value-list` 枚举字典与 `actions`，将原始数字枚举码在源头转换为可读描述或标准特征，补齐 `device_model` 与 `original_name`，放开扫地机、电饭煲、监控、空调、洗衣机等家电的安全控制映射。
   - 扩充 `ha-registry.ts` 与 `ha-rest-transport.ts`：支持 `开关 按键` 等主控开关识别，保留 `options`、`min`、`max`、`step` 等控制属性快照。
2. **领域聚合层（`@super-looi/home-devices`）**
   - 净化主开关选举（`findPrimaryPowerEntity`）、设备分类（`classifyAppliance`）与温度/传感器单位归一化（`°F -> °C`）。
   - 为**监控（`camera`）**、**扫地机器人（`vacuum`）**、**电饭煲/周期家电（`cooker`/`washer`/`dishwasher`/`microwave`）**、**环境温控（`climate`）**、**灯光/多键开关/智能插座/宠物喂食器**构建深度结构化领域模型（例如扫地机的清扫状态枚举表、电量、清扫面积/时长、吸力/水量档位、主刷/边刷/滤芯/拖布 4 项耗材寿命与回充/集尘/洗拖布动作；监控的实时画面状态、休眠/移动侦测/水印开关、夜视/录制模式、存储卡容量与事件流）。
   - 扩充 `layout-store.ts`：支持自由移动/任意两卡片位置互换（`swapApplianceOrder` / `moveApplianceOrder`），让长按编辑模式指哪打哪。
3. **状态同步层（`apps/nsh/store.ts`）**
   - 进入 `home` 空间时立即触发 `syncHomeDashboard()`，并在 `activeSpace() === "home"` 且应用在前台时每 `4000ms` 自动静默拉取最新设备状态（外部米家 App 或实体墙壁开关操作后自动刷新）。
4. **视图与图标层（`apps/nsh/ui/HomeIcons.tsx` & `HomeSpaceView.tsx`）**
   - `HomeIcons.tsx`：基于 `Canvas` 矢量绘制的高清语义图标库（ApplianceIcon + ActionIcon），零文字依赖、完美适配深浅色主题与多语言。
   - `HomeSpaceView.tsx`：
     - **Bento 桌面态**：带设备矢量图标、清晰状态副标题与圆形电源图标按钮（`⏻`）；**长按任意卡片**进入网格自由编辑模式（支持自由改 `1×1` / `2×1` / `2×2`、方向移动与点击目标卡片互换位置）。
     - **独立全屏设备页（Full-Page Detail View）**：点击监控、扫地机器人、电饭煲、空调、灯光、多键开关等卡片时，切换到**全新的独立专属页面**（含顶部返回栏、设备专属主视觉舞台、实时遥测看板、档位选择器、动作控制坞与耗材/事件面板）。
