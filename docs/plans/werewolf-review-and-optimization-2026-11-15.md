# 狼人杀功能审阅与优化方案

## 审阅依据

审阅对象为 2026-11-15 当前工作区，包含未提交的狼人杀恢复与舞台相关修改。依据包括狼人杀原生 UI、手机副屏页面、规则引擎、运行时、语音与 LAN 接口，以及 `docs/artifacts/werewolf-e2e/` 留存的横屏截图。截图用于观察布局，当前行为以源码为准。

执行 `pnpm --filter @super-looi/nsh test:werewolf`，19 项测试全部通过。另以临时命令调用实际引擎，复现了未确认任何身份牌即可进入首夜：`dealing / 0 人确认 → night_intro / 6 人确认`。本次没有重新执行手机真机对局。

## 整体判断

现有功能已经覆盖 6／9／12 人预设、自定义配牌、神职技能、警长与平票流程、双端交互、语音主持、对局检查点和终局复盘。确定性规则与 AI 主持分开，适合继续演进。

影响真实聚会体验的重点是：身份相关 UI 没有全部纳入防窥范围；恢复保存了规则进度，却没有完整保存玩家连接入口；少数主要按钮会静默跳过尚未完成的玩家操作。应先补齐这些行为，再优化界面的阅读顺序和主持节奏。

## 已确认的功能问题

### P1：狼人副屏白天直接暴露阵营

- 触发：存活狼人在警长竞选、天亮播报或白天讨论阶段打开副屏，身份牌保持遮挡。
- 结果：页面仍显示“狼人白天战术”和“狼人拍刀自爆”，邻座不需要看到身份牌即可判断其阵营。
- 位置：`apps/nsh/plugins/werewolf-judge/runtime/lan-companion.ts:660`；角色条件来自 `runtime/engine.ts:693`。
- 优化：所有玩家默认显示相同的“我的操作”入口；身份、角色技能和查验信息统一放入私密操作区域。收起、松手或页面进入后台时一起隐藏敏感内容。
- 成本：修改现有副屏的渲染与交互状态，复用现有角色数据和动作接口。

### P1：冷启动恢复缺少原 LAN 端口

- 触发：已认领座位的对局在 App 进程重启后恢复，主机 IP 未变。
- 结果：`lastLanPort` 只保存在内存，恢复时没有原端口，原生房间会请求随机端口。端口一旦变化，旧网页仍访问旧端口，新扫码页面又因浏览器 origin（协议、主机与端口）变化而读取不到原座位凭据；服务端仍将该座位标为已占用。
- 位置：`runtime/index.ts:276`、`:379`、`:1387`、`:1675`；`runtime/engine.ts:580`；`apps/nsh/src/lan_room.rs:150`。
- 优化：将最后实际使用的端口纳入现有检查点，在重新打开 LAN 房间前恢复。先覆盖“主机地址未变、进程重启”的直接路径；端口保留本身不解决主机 IP 改变。
- 成本：扩展现有检查点和恢复逻辑，兼容旧检查点中缺少该字段的情况。

### P1：未领牌即可被批量标记为领牌完成

- 触发：LAN 发牌尚未完成时点击主界面高亮的“全员进入首夜”。
- 结果：`beginFirstNight()` 将所有座位的 `dealtConfirmed` 设置为 `true`，随后进入夜晚。临时引擎探针确认 0／6 已确认也能进入首夜。
- 位置：`ui/StageCanvas.tsx:519`；`runtime/engine.ts:1006`。
- 优化：普通进入首夜动作要求所有身份确认完成，并展示“已领 4／6，等待 2、5 号”。已有逐座代确认功能可用于处理无手机玩家，避免普通推进动作暗中替全员确认。
- 成本：在现有引擎入口约束阶段条件，UI 复用 `dealtConfirmed` 派生按钮状态，不增加新的“准备”实体。

### P2：暂停舞台后副屏仍可推进对局

- 触发：主持人退出舞台，对局进入 `hostPaused`，玩家仍在原副屏提交夜间技能或选票。
- 结果：LAN 房间保留；认证动作进入串行队列后直接修改引擎，没有检查暂停状态。最后一票可触发结算，夜间技能也可能推进阶段。
- 位置：`runtime/index.ts:314`、`:870`、`:1429`；副屏投影 `runtime/engine.ts:704` 没有暂停状态。
- 优化：在串行队列实际执行动作时检查 `hostPaused`，向副屏投影暂停状态并暂时禁用提交，保留本地草稿。恢复后按原阶段继续。
- 成本：复用已有暂停状态，调整运行时动作边界及副屏状态投影。

### P2：提前结束投票的实际后果没有体现在按钮上

- 触发：尚有人未投票时点击“结算公布票型”。
- 结果：引擎把所有未投票玩家写成弃票，按钮始终是高亮主操作；玩家容易把“公布”理解为展示已有结果。
- 位置：`ui/StageDrawer.tsx:1574`；`runtime/engine.ts:1573`。
- 优化：收票时突出“已投 4／6，等待 2、5 号”；全票到齐按现有流程结算。主持人提前结束保留为次级操作，直接命名“提前结束，未投视为弃票”，让操作名称说明真实结果。
- 成本：复用已有投票人数和 `finalizeVotes()`，调整入口层级及文案。

## UI、产品与玩家体验优化

| 场景 | 当前问题 | 优化后的行为 | 对玩家的价值与成本 |
| --- | --- | --- | --- |
| 开局大厅 | 人数、板子术语、触控方式、警长和底座模式同时出现；6 人预设没有守卫，仍常驻“同守同救奶穿” | 按“人数／板子 → 共用主机或各自手机 → 入座发牌”组织；规则摘要常驻，细则按需展开；只显示对当前牌组生效的选项 | 新玩家更快理解开局；只调整现有信息层级与条件渲染 |
| 发牌 | 主机默认逐座环视、头像、查牌、代确认与进入首夜并列，缺少明确的等待对象 | 当前座位、已领人数、未确认座位和“下一位”形成一条阅读路径；头像抓拍作为次级动作 | 降低主持人反复解释和逐个查人的负担；保留现有发牌顺序 |
| 白天发言 | 当前玩家和倒计时在胶囊与桌面重复，大片表情与操作区竞争；“进入公投”比“下一位发言”更突出 | 主视觉显示“3 号 阿凯 · 余 42 秒”，辅以“下一位 4 号”；发言期间主操作为“结束本次发言”，提前公投作为次级动作；表情服从当前任务的空间需求 | 围桌玩家抬头就能知道谁说话、何时轮到自己；复用座位昵称、发言顺序和计时数据 |
| 手机投票 | LAN 模式仍默认出现“选择投票座位，再代该座位投票”的主持人表单 | 主机默认只展示收票进度；玩家在各自手机投票；已有主机代投表单通过“代操作”展开 | 公共桌面和私人选择职责明确；保留无手机玩家的现有操作能力 |
| 夜间操作 | “防窥盾”“0ms 瞬时遮蔽”“应急本机操作”等措辞偏实现；不同操作的主次不够直观 | 使用“按住查看，松手隐藏”“主机代操作”；动作按钮直接写“守护 3 号”“查验 5 号”“今晚不用药”；选中目标与提交完成清楚区分 | 玩家能预测点击结果；复用当前动作和选座状态 |
| 公共状态 | 全场主要看到“存活、扫码人数”，缺少具体的等待对象 | 发牌／投票显示未完成的公开座位；夜晚仅展示公开阶段，不公开哪名玩家尚未提交 | 减少催促，同时不以进度提示暴露夜间身份；使用已有公开数据 |
| 终局复盘 | 再来一局、全员底牌、AI 点评和时间轴竞争有限横屏高度；AI 固定采用“毒舌幽默”口吻 | 首屏集中显示胜负、底牌和关键回合；AI 点评只引用实际技能、票型等记录，帮助玩家理解本局转折；再来一局保留清楚入口 | 复盘更有讨论价值；复用已有真实时间轴和战报，不引入额外评分系统 |

视觉实施时沿用当前深色桌游风格、语义颜色和舞台姿态。主要调整信息权重、空间分配、按钮数量与文案；6／9／12 人布局均以横屏为目标。与已有 `stage-ui-anti-occlusion-and-ux-plan.md` 合并处理字幕遮挡、发牌按钮挤压和抽屉空间问题，避免两套布局方案重复修改同一处。

## 技术边界与取舍

1. **保留有状态的 `WerewolfEngine` 类。** 它拥有本局规则、投票和阶段生命周期；拆成一组共享可变状态的函数会使调用方承担更多顺序约束。进入首夜等规则条件由引擎负责，两个 UI 读取规则结果展示状态。
2. **暂停和 LAN 生命周期仍归运行时。** UI 请求动作，运行时在执行时检查暂停，调用引擎并驱动语音、舞台和存储。LAN 端口属于运行时资源信息，随现有检查点保存；不让规则计算依赖网络服务。
3. **优先修正两个界面的行为一致性。** 主机与副屏都调用现有引擎规则，不在各页面重新实现“是否能推进”。角色敏感内容的显隐在副屏私密区域集中处理；不为这次优化引入流程 DSL（领域专用语言）、通用工作流框架或新依赖。
4. **测试补到真实缺口。** 增加未领牌不能普通开夜、暂停期间 LAN 行动不改变状态、冷启动后旧浏览器连接和座位仍可用、遮牌状态不出现角色专属入口这四类行为覆盖。现有 19 项测试通过并未覆盖这些完整路径。
