# 家居控制与表情控制接入 LOOI 语音

## 1. 目标与当前缺口

在现有 LIVE 对话中，通过自然语言查询和控制家居设备、要求 LOOI 做表情，并组合两种能力。例如：“卧室风扇调到二档”“客厅灯全关，再做个晚安表情”。简单控制直接调用实时语音工具，复杂任务继续使用现有 Pi Agent。

默认范围：家居能力对齐现有页面；表情支持明确口令与自主表达；首版支持房间批量操作和组合指令。

代码依据：

- 实时语音直接注册任务提交、任务管理与底座控制；家居仅有 Pi 工具，控制参数仍局限于开关、亮度和色温。
- 家居页面已采用 `ApplianceControlPrimitive` 的 `toggle / range / choice / action / metric` 五类能力。旧工具查询使用另一组 gateway 实体，不能完整表达页面能力。
- 72 个表情已有渲染实现；store 直接依据语音、任务及前后台状态设置表情，会覆盖语音请求的新表情。

## 2. 接口与职责

### 家居：统一能力查询与执行

在现有 `HomeRuntime` 增加面向工具的查询和控制方法：从 `dashboard()` 的设备及 `capabilities.controls` 投影出设备身份、来源、房间、在线状态、读数和控制能力；复用现有连接、命令队列及 `HomeControlResult`。不把卡片布局数据发给模型。

| 工具 | 参数 | 行为 |
| --- | --- | --- |
| `list_home_devices` | `query?`、`offset?` | 按设备名、房间、类型、能力标签搜索；沿用每页 30 项及 `next_offset`；返回 `connectionId`，设备包含 `applianceId`、来源及 controlId |
| `control_home_device` | `connectionId`、`applianceId`、`controlId`、`value?` | 将能力和目标值转换为现有命令，交给 `HomeRuntime.control()`；返回原有回执及实际目标值 |
| `set_looi_expression` | `expression`、`intent`、`duration_ms?` | 请求展示指定表情；intent 为 `explicit` 或 `autonomous`，返回是否应用及持续时间 |

家居值约定：开关使用显式布尔目标；数值使用返回的单位；选项使用返回的 option value；动作不传 value；读数只参与查询。语音 schema 沿用现有字符串字段，由适配器转换布尔、数值与分页参数，Pi schema 使用对应原生类型。

在 `packages/home-devices` 提取一个无状态的“控制元语 + 目标值 → HomeControlCommand”转换函数，供页面和 HomeRuntime 共同使用。集中处理开关自定义 service/data、亮度百分比换算、数值范围与步长、选项数值转换、动作固定参数；复用页面现有换算行为，并返回实际目标值。页面继续使用 UI 事件入口，只替换重复命令拼装。

调用示例：查询“卧室风扇” → 得到风扇、风速 controlId 和四档选项 → 传入查询返回的二档 value → 根据回执口述结果。模型无需了解 MIoT 属性编号或 HA service。

`VoiceRuntimeOptions` 注入 `listHomeDevices`、`controlHomeDevice` 回调，沿 Runtime → Session → 工具注册层传递；应用层连接同一个 HomeRuntime。Pi 的两个同名工具同步迁移，保留现有任务动作记录与审批配置。实时语音直接执行本轮工具调用，不伪造 tap 或创建 Pi 任务；宿主按会话和 callId 生成 requestId，复用现有去重。直接语音结果进入现有 Realtime 工具追踪，不迁移任务证据表。

将 store 中现有命令反馈提取为 `dispatchHomeCommand(command, execute)`：共享 `HomePowerState.control`、最终刷新和摄像头关闭前停止预览。应用层的能力控制方法提供内部 dispatch 回调，解析出命令后将命令与真实执行闭包交给 store；不提供时直接执行，供 Pi 复用。UI 闭包仍用原来的 action 身份，语音闭包使用真实会话/callId；共用包装向上传递异常，UI 自行保留通知处理，不复用当前会吞异常返回 null 的 UI 方法。这个回调只协调现有显示状态，不创建新的设备状态副本。

同名设备返回候选并询问位置；明确的“客厅所有灯”枚举该房间灯具，逐设备调用同一工具、分别返回回执。部分成功时报告成功项与未完成项。来源逐设备标识；未要求演示时只控制真实来源；MIoT 与 HA 的相似设备沿用现有身份规则，返回来源供消歧。控制结果经过共用刷新入口；`verified` 才说明已完成，其余按原回执说明，不自动重发。

摄像头开关、模式等已暴露能力使用同一路径。视频预览和图像理解沿用摄像头专项计划。

### 表情：统一显示决策

保留 `RobotFaceController` 的渲染、眨眼和音量反馈职责。在 store 增加语音覆盖状态（表达 ID、意图、到期时间）及一个释放计时器，通过纯选择函数决定最终表情：后台 sleeping → 明确口令 → 吸合/脱座瞬态 → 自主表达 → 原有语音/任务/空闲状态。

- 明确口令支持全部 72 项；默认 4 秒，用户指定时支持 1～15 秒；新明确口令替换旧口令。
- 自主表达默认 2.5 秒，没有明确口令覆盖时才接收；用户下一次开口即清除自主表达。聆听/说话阶段切换不覆盖仍有效的表情，音量与眨眼继续遵循现有配置。
- 自主表达集合为第 13～48 项（喜悦亲昵、小脾气、日常陪伴），另加 `curious / aha_eureka / confused / wave_bye`。集合从现有 catalog 导出。其余状态、环境表情由实际状态或明确口令触发。
- 表情只改变屏幕表现；表演“睡觉脸”不会结束对话，表演“隐私脸”不会改变麦克风状态。相关功能仍使用其原有控制入口。
- 结束会话、切后台、销毁 store 时清除覆盖与计时器。用户打断清除自主表达，保留未到期的明确表演。

提取 FaceProbe 已有名称为共享 catalog 元数据，补充英文名称和简短用途，供试镜页及模型说明复用。expression 枚举直接使用 `FACE_EXPRESSION_IDS`。语音通过 `setExpression` 回调请求 store 展示；目标同步到 controller 后返回应用成功。

新增 `onUserSpeechStarted` 回调，贯穿 VoiceRuntimeOptions、LiveVoiceSessionOptions 和 store；由现有归一化的用户语音/转写开始事件触发，用于清除自主表情。不能只监视 phase，因为用户开口前后可能始终处于 listening。会话结束、错误、后台及关闭的已有状态通知统一清理覆盖。

### 会话：组合指令与按轮续说

更新提示词：普通家居请求优先直接工具，先查设备与能力；情绪合适时自主表达，普通回复不要求每轮换表情；仅表情口令不朗读工具名或舞台说明。复杂任务继续使用原有 Agent 协同。

组合指令复用多次调用，不增加批量工具或工作流引擎。有先后关系的指令由模型分轮执行，如“关灯后笑一下”先取得家居回执再请求表情；无先后要求时允许同轮操作。

当前 OpenAI 每条工具回执都会产生 `response.create`，多工具同轮会重复续说。完整参数到达即执行工具，回传分组遵循现有协议差异：OpenAI 按 responseId 收集，待该响应的 `response.done` 与全部结果齐备后统一回传；豆包以单个完整 `tool_calls` 事件中的 calls 为一组，结果齐备即回传，不等待 responseId 或 `response.done`。当前豆包用例允许无 responseId，并在收到工具结果后才结束口述，不能强加 OpenAI 的分组条件。

协议以 `encodeToolReplies(results)` 替换单个 `encodeToolReply`：豆包一个消息携带多项结果；OpenAI 写入全部 function outputs 后仅发送一次 `response.create`。

业务工具返回执行结果，不自行发送协议消息；注册层统一收集、回传与维护 busy。任务提交、任务管理和底座工具同步迁移，后台通知保留现有空闲调度。未知工具名返回工具错误，移除当前默认转交 `run_agent_task` 的分支。

关闭会话后不回传旧结果、不启动尚未发出的控制；已发往设备的命令按原队列收尾。在现有 HomeAction 增加可选宿主谓词 `canDispatch()`，排队命令在出队且发网前检查该会话仍有效；不满足则不发送。不要使用现有 signal abort 实现此行为，因为它会使共享家居连接整体失效。工具未完成时保持 busy，不触发用户空闲结束。已取消或被新轮次取代的响应不能续说，结果不会进入下一会话。

### 复杂度取舍

- “能力 ID + 值”需要查询结果映射，但能让页面、Pi 与语音共享转换，无需按风扇、空调、灯具各新增工具。
- 命令转换使用纯函数；连接和队列属于 HomeRuntime；表情计时属于 store。不新增长期服务类、依赖、数据库表或项目。
- 轮次聚合放在现有注册层和会话层，直接解决组合指令的重复续说，不另建调度框架。

## 4. 验证与完成标准

自动化覆盖：

- 共享转换：灯具开关/亮度/色温、风扇档位/摇头、空调温度/模式、动作固定参数；同一目标在页面与语音生成相同命令。
- 家居工具：设备/房间/能力搜索与分页、模拟来源、同名候选、旧连接、回读；保留 `verified / rejected / unknown`，多设备逐项返回结果；页面与语音交错控制不被旧乐观状态覆盖，语音关闭摄像头同步停止预览。
- 表情：72 项明确调用、自主集合、明确口令优先、到期恢复当前状态、用户打断、吸合、会话结束及后台清理。复用原有渲染测试。
- 双协议：握手注册新工具、先查后控、同轮结果乱序回传、家居与表情组合、旧会话结果隔离；OpenAI 单轮只发一次续说，豆包无 responseId 且未收到 done 时仍返回结果；结束会话阻止尚在队列中的设备命令，但不破坏家居连接；原有后台汇报、打断与空闲休眠回归。

使用 pnpm 运行受影响包的测试和类型检查，涉及 home-devices、home-assistant、runtime 协议测试，以及 NSH 的 `test:voice-runtime`、typecheck；通过现有打包链路重建生成物。按实际 UI 改动运行对应 NSH UI 用例。

在已连接 Android 开发真机验证真实麦克风；可用 iPhone 开发设备执行同一组验收。不安装模拟器包。两种 Realtime 提供方分别验证工具回传和续说，使用现有配置与凭证。

1. “卧室风扇调到二档”“空调设到二十六度”“台灯亮度三成”：设备变化、回读、页面及口述一致。
2. “客厅的灯全关”：仅命中指定房间灯具；“打开台灯”有多个候选时询问位置，混合结果不概括为全部成功。
3. “笑一个”“眨眨眼”“来个猫咪脸”：回复中可见目标表情，到期后恢复；自主表达在用户下次开口后恢复倾听。
4. “关卧室灯，再做个晚安表情”：按顺序执行；结束 LIVE 或切后台后无遗留表情计时。

完成标准：简单控制由直接工具完成；设备、回执、表情与口述一致；自动化通过，真机结果和受设备/凭证条件限制的验证项分别记录。
