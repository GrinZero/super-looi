# Codex CLI 升级与云端目录

## 职责

Codex 插件设置页调用插件 runtime 检查版本、安装版本、读取云端环境。App Linux 运行从 npm 官方稳定发行渠道安装的 ARM64 musl 客户端。首次运行使用内置版本。App 的 HTTPS 接口把官方发行包以流式方式写入临时文件，Linux guest 使用现有挂载读取文件。解包和试运行完成后一次切换 CLI 与 Code Mode host（代码执行宿主），沿用原来的 Codex 登录目录。启用过独立升级的安装优先使用独立安装版本。

版本模块负责 npm 元数据、发行文件布局、一个安装事务。Cloud 模块使用 App 内 CLI 的登录凭据读取新版个人、工作区目录和旧版目录。插件 runtime 管理登录、任务与升级的并发，设置页通过已有插件命令和快照通信。这让调用方只处理版本与环境状态，代价是 App 要维护官方 npm 发行包布局和 Cloud 目录响应格式。

新版目录内的环境按服务端配置 ID 保存。稳定版 `cloud exec` 只接收旧版环境，插件对新版配置显示提交兼容性，并在工具回执中返回同一原因。新版 Cloud 的分支来自已保存的环境配置，旧版仍可指定分支。目录接口返回环境名称和 ID，具体分支待通过环境详情读取。新版提交协议和分支覆盖待上游提供可调用的入口，见 [Cloud 兼容性调研](../codex-cloud-cli-compatibility-research.md)。

## 设置页动效

| 状态变更 | 表现 | 减少动态效果 |
| --- | --- | --- |
| 检查、升级、刷新和保存按下 | 使用现有按钮的按压颜色和焦点环 | 保留即时颜色反馈 |
| 环境选择 | 使用共享 Select 的底部选择面板和选中标记 | 使用共享控件设置 |
| 检查、下载、目录加载、失败 | 同位置更新按钮或状态文字 | 即时更新 |
| 选择环境后分支说明变化 | 在云端卡片内按所选环境显示 | 即时更新 |
