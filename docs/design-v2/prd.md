# Phone Agent 产品需求文档

## 产品结论

建设一个以手机为感知与交互入口、以 LOOI 为身体、以 DeepSeek Harness 为任务执行内核的个人 Agent。默认横屏驻留为一个有表情、有注意力、可交谈的宠物；它持续整理经授权的现实上下文，能够解释自己记住了什么，也能完成家居控制、资料整理、远程工作等实际任务。

建议沿用 super-looi 的 React Native／Expo、BLE、语音、Postgres 与 Mem0 基础，新增可追溯的上下文系统、独立身体控制器、家庭连接层和持久任务管理。家庭主机先承载 Harness、任务和记忆索引；模型推理由配置选择本地或云端，不要求家庭主机运行大模型。手机保留即时交互、感知门控和停止能力。dsh-Go 的移动任务体验值得参考，直接复制其整个运行环境并非第一版必需。[S01][S02][S06][S10]

版本 0.2 · 2026年11月2日 · 工作名称 Presence。本文定义可执行的产品方案；界面中的设备数值、任务与记忆均为设计示例。文中的时延、成功率、周期是验收目标或工作量估计，本轮没有连接用户设备做实测。

### 首个完整价值闭环

用户在桌边说“记住这个”，Agent 将语音与当时画面关联成可回看的记忆；稍后用户询问时，它给出最后观察时间及依据。用户接着说“打开书房灯，继续刚才的 Godot 构建”，它分别完成设备回读和远程任务，日常界面仍保持宠物形象，用户要求查看时再打开功能页。

### 三项产品承诺

- 上下文连续：少让用户重复解释，分得清当前事实、历史观察和不确定推测。
- 行动可核验：家居看设备回报，工作看产物与执行记录，机器人动作由本地控制器监督。
- 相处可掌控：用户能暂停感知、纠正记忆、撤销任务；主动性有范围、频率和明确的停止条件。

## 1 用户与产品边界

### 首要用户

第一阶段面向单一家庭中的技术型个人用户：有 Android 手机、LOOI 底座、Mac 或常开电脑，使用米家／HomeKit，并希望把日常情境接入自己的生产力工具。用户正在做 Godot 游戏与 Agent 工程，适合作为首轮真实使用场景；这不要求产品永远只服务开发者。

待配置时确认的变量包括手机具体型号、LOOI 固件、家居型号与账号地区、是否已有 HA、是否有常开主机。当前设计按 Android 16、前台横屏 dock、家庭局域网、单 owner 的私人 alpha 推进，不把未知设备兼容性写成承诺。

### 使用模式

| 模式 | 感知与身体 | 任务与界面 |
| --- | --- | --- |
| 桌面陪伴 | 用户开启后持续本地采集与事件筛选；底座可用 | 默认全屏宠物；任务在后台继续 |
| 专注工作 | 保留必要感知；降低主动说话和动作频率 | 只提示阻塞、约定提醒和完成结果 |
| 拿起手机 | 撤销运动权限；摄像头降为主动触发 | 竖屏继续查看、审批和执行任务 |
| 离开 App | 摄像头按产品策略暂停；符合条件的麦克风服务单独验证 | Hub 上任务继续；状态通过通知恢复 |
| 隐私暂停 | 关闭相机、麦克风与自动观察，清空短时缓存 | 可触摸查看任务；触摸恢复感知 |
| 主机离线 | 触摸停止、隐私开关、宠物状态、缓存读取及经验证的本地关键词可用 | 新工作可保存待提交意图；物理动作不排队补发 |

Android 的 Camera／Mic 前台服务受 while-in-use 与后台启动限制，因此“持续”首先指用户主动启用的前台桌面会话，不承诺锁屏、口袋中和任意后台状态的全天采集。[S27]

### 产品范围

MVP 同时覆盖陪伴、事件记忆、有限主动观察、少量家居实体和一个远程生产力工作区。暂不建设全屋导航、全 App 无人值守操控、家庭成员自动身份画像、无条件全天云端视频理解。iOS 和手机内置 Linux Harness 作为后续适配路线。

## 2 如何衡量它真的懂用户

核心指标为“有证据支持、被用户认可的有效闭环次数”，按找回上下文、减少重复解释、完成工作、完成家居动作分别计数。重复一句旧信息、播放动画、存入更多数据本身不计价值。

| 维度 | 观测方式 | Alpha 目标 |
| --- | --- | --- |
| 有用的记忆 | 有答案且来源／时间正确的问题占比 | 固定测试集 ≥90% |
| 知道自己不知道 | 证据缺失题正确保留不确定性 | ≥95% |
| 不乱打扰 | 非请求主动提示被评价有用的比例 | ≥70%，默认最多3次／日 |
| 少重复解释 | 完成同类任务所需的补充说明次数 | 对比无记忆基线下降，记录实际幅度 |
| 任务可信 | 所有成功状态都对应产物／回读 | 测试集中100%可追溯 |
| 用户可控 | 暂停、撤权、纠错、删除跨层生效 | 所列强制用例全部通过 |

目标仅用于 alpha 验收，不能外推为家庭使用准确率。主动性阈值先在 shadow 模式记录“本来会提醒什么”，由用户评分后再开放。

## 3 五个核心场景

### 场景 A 记住物品但不伪造实时位置

用户把钥匙放在键盘左边，说“记住钥匙放这儿了”。Agent 用同一时段语音和清晰源帧建立放置事件，短暂回答“记住了”。两小时后用户问“钥匙在哪”，回答“我最后在19:42看到它在键盘左侧”，可按要求展示原图。若之后相机被遮挡、位置发生变化或证据已到期，明确说明观察边界。它不会把“没有看到钥匙”改写为“钥匙不在房间”。

验收：改变位置、移出视野、相似钥匙、弱光和时间跳变五组情况，答案不得丢失时间、主体或不确定性。

### 场景 B 情境辅助家居控制

用户说“把书房灯调暖一点”。Agent 解析到唯一实体，检查支持色温的能力，发出有界目标状态指令，收到新状态后回复“书房灯已调暖”。一次性的调整只留事件；连续几次相似选择可以提出“要把这个设为晚间默认吗”，确认后才成为偏好。新风建议必须来自已接入传感器，不由画面猜测 CO₂。

验收：房间歧义先消歧；回读缺失显示等待反馈；设备实际状态与视觉冲突时保留两种来源。

### 场景 C 现实上下文进入生产力任务

用户讨论海岛城池模型后说“把刚才说的道路和阶梯问题整理成清单，放到这个项目，再在 Mac 上跑一次构建”。Agent 仅取获授权的这段语音、项目关联与目标工作区，建立独立任务。用户可以继续与宠物说话；任务不会占住语音会话。完成时轻量提示，用户说“打开任务”才显示产物、构建结果与下一步。

验收：产物能打开、关联正确项目；不得把全部家庭音视频传给 coding worker；手机断网再连接后任务仍有可恢复身份。

### 场景 D 有目的地改变观察角度

用户问“键盘旁边那是什么”。当前图像部分遮挡时，Agent 先确定缺少什么证据，在已授权、安全且有校准的范围内请求调整视角。身体控制器短时执行、停止，再拿稳定的新帧重新判断。一次观察没有收益就停，必要时请用户移动物品。头部俯仰先行；轮式原地转向必须先通过固件失联停止验证。

验收：每次动作都有目标、预算、前后证据和终态；没有精确角度反馈时不显示“已转动15度”。

### 场景 E 暂停与恢复

“先别看”关闭摄像头、保留当前语音对话；“进入隐私模式”停止音视频采集、观察任务和身体自主动作，清空易失缓存。全部麦克风关闭后，只能触摸恢复，界面不再提示说唤醒词。已经发出的工作任务可继续，用户仍可选择停止它们。

验收：暂停后无新采样、无迟到片段入库；如存在已提交云服务的请求，展示其独立处理状态，不能声称已经撤回外部已接收数据。

P0 指可验收的技术与产品闭环，P1 指私人日用 alpha，P2 指后续扩展。核心愿景在 P1 中完整出现；P0 用于消除硬件与平台风险。

### 功能依赖

持续自动记忆上线前，必须先有依据、纠错和删除。主动身体运动上线前，必须先有原生停止、动作租约与固件故障验证。家居自主执行上线前，必须先有实体允许清单和回读。长任务上线前，必须先有持久 task ID、授权与取消状态。

已有仓库具备原型基础，但连续视频、部分设备录音／视频工具和方向检测仍有占位实现；移动的 speed 参数尚未进入控制指令。产品范围以实际代码能力为基线，不能靠 UI 显示将其视为已完成。[S11][S12][S13][S14]

## 5 首次设置与日常入口

首次设置分为五步，每步可跳过相关能力：连接或创建本地身份；试用语音与宠物；选择感知模式；配对底座并完成停止测试；连接家庭与工作主机。先展示可用体验，再按功能逐项请求权限。摄像头权限、持续事件整理、原始媒体保存、云端模型上传是独立选择。

设备连接页记录型号、固件、连接方式、允许动作、最后验证时间；发现失败给出重试与手动选择，不能自动连上同名陌生底座。Hub 用一次性配对码或二维码建立信任；家庭连接采用正规授权流程，不把管理员长期 token 的手动粘贴设计成默认路径。[S43]

新用户先进入“指令模式”：本地唤醒与主动请求的观察。打开“桌面感知”后，才处理背景语音片段和环境变化；告知同住者的提示可见。访客模式保留当前对话能力，默认不将访客声音／面孔建立长期个人档案。

## 6 宠物交互与信息架构

### 驻留层

默认横屏只有原创双眼、轻量表情与低干扰的真实采集状态。待机、聆听、理解、说话和短时执行由眼神、眨眼及极少字幕表达。长期任务运行不要求一直显示加载圈；宠物可以回到自然驻留。没有常驻任务侧栏、设备网格或底部功能标签。

触摸脸或上划打开快捷抽屉；“打开记忆”“看看任务”“打开家居”映射到确定页面。侧滑／系统返回关闭页面，回到宠物。纯色变化不承担唯一状态提示，听障用户可启用长期字幕，减少动态效果可关闭大幅动作。

### 轻反馈层

一句话结果、待处理提醒或有限动作理由可短暂出现，默认约3秒；用户正在说话、开会或专注时排队。主动信息不会自动打开完整功能页面。需要审阅变更时先说“准备好了，打开任务可以看”，用户手动或语音进入后再展示详情。正在运动的停止按钮始终可触达，是持续控制状态的一部分。

### 功能层

| 页面 | 进入方式 | 必须回答的问题 | 对应设计屏 |
| --- | --- | --- | --- |
| 快捷抽屉 | 点击／上划／语音 | 我现在可以去哪里 | 05 |
| 记忆时间线 | 打开记忆 | 它记住了什么，哪些只是推测 | 06 |
| 记忆证据详情 | 点记忆／为什么 | 何时、从哪得到、是否过期、如何改正 | 07 |
| 任务列表与详情 | 打开任务 | 在做什么，在哪执行，有何产物／等待 | 08、09 |
| 家庭控制 | 打开家居 | 哪个实体，当前状态多新，是否已回报 | 10 |
| 隐私控制 | 暂停感知／触摸入口 | 相机、麦克风、留存现在是什么状态 | 11 |
| 设置与连接 | 首次启动／设置 | 能力是否已接通，缺哪个步骤 | 12、14 |

### 相互独立的状态

宠物表情、采集模式、身体状态、连接状态与任务状态分开建模。用户可以在“说话”时有任务运行，也可以在“隐私暂停”时查看旧任务。UI 不应以单一 loading 布尔值推导整个 Agent 的状态。

## 7 语音会话要求

本地先响应唤醒与停止播放，再完成 ASR 和理解；自有 TTS 音频要标记，避免被再次记成用户发言。原生 Audio Session Manager 统一占用麦克风，负责 AEC、VAD、来电、蓝牙耳机变化和 barge-in。声纹仅提供弱身份线索，重要动作不能只凭相似声音授权。

用户中途改口时，更新当前未提交意图；已提交动作必须先取消／核实，不能用新句子静默覆盖。短暂沉默只关闭当前聆听窗口，不表示用户同意，也不自动推进长期任务或学习关卡。识别不确定时保留原话并做一次简短澄清，不把不完整 ASR 写成确定长期事实。

## 8 连续感知与主动性

### 连续采集与长期保存分开

授权后的桌面模式持续在本地处理声音和低成本画面信息。系统只对有价值的片段产生事件，再选择有限证据分析、保留和检索。采集帧率、保存帧率、视觉模型调用频率独立设置；提高其中一个不能直接代表记忆更准确。

Screenpipe 仅作为内部实现参考：研究它的采集调度、去重、证据关联、语义投影和检索方式，自行实现手机摄像头与语音上下文管线。产品不依赖 Screenpipe 安装、API、MCP或桌面录制。这里的“桌面感知”指手机放在LOOI底座上观察现实环境；SSH与已有App仍是独立的生产力扩展。

优先触发包括用户明确“记住”、与当前话题有关的物品放置、已授权区域出现明显变化、家居状态异常、当前任务请求补充视角。没有价值的重复帧、静音、自己的播报、明确排除区域不晋升为长期记忆。连续镜头没有覆盖到的活动应标记为未观察。

### 主动观察的产品约束

每个观察请求包含问题、缺失信息、允许区域、可用动作、最大尝试次数、时限和预期产出。MVP 默认最多一次身体调整、最多两次新帧验证，身体动作与取帧预算约3秒；视觉模型分析另设超时，不允许电机持续运动等待模型结果。这些是初始参数，需按真机测试修改。没有收益、用户打断、前台丢失、底座移除、温度过高或连接失效立即终止。

全屋闲逛和随机转向不属于默认“陪伴”。表情动画与机械运动分开，宠物好奇的眼神不自动变成轮子动作。用户可以选择静态宠物、只允许俯仰、或已验证的有限转向。使用经校准的离散指令与脉冲长度，速度暂作为实测结果，不能把当前未生效的 speed 参数设计为可调能力。自身播音、动作和灯光变化标记为自生成事件，避免再次触发记忆与观察。

### 主动提醒与自动执行

主动提醒使用证据相关性、时效、用户可打扰性与频率预算共同筛选。起始默认每天最多3次非请求提示、同类事件冷却30分钟；用户直接请求和紧急停止不受此提醒预算限制。

主动家居执行只能来自可审阅的规则，例如“我明确开启专注模式时，把书房台灯设为30%，今晚有效”。规则包含条件、目标、参数范围、持续期和撤销入口。单次偏好、沉默或相机看到动作不形成长期授权。

## 9 记忆产品要求

每条可见记忆至少有内容、类型、主体、观察时间、来源、状态和管理入口。重要回答能展示“根据什么”；无法回溯的历史数据标“来源不完整”。位置类内容始终写成最后观察，家居类内容同时带新鲜度，偏好区分本次、时间段和长期。

用户可执行四种不同操作：改正事实；将推测标为不成立；忘记某条推断；删除原始片段及派生记忆。产品应明确影响范围并提供删除状态。用户主动删除后，搜索索引、摘要、缓存和任务上下文中的衍生副本都需要失效。

偏好、事实和执行授权分别管理。一个“喜欢昏暗灯光”的记忆可以帮助提出建议，不能自行授权开关灯；一段成功的 SSH 流程记忆可以帮助复用步骤，不能自动取得上次工作区之外的写权限。

:::page

## 10 家居能力要求

建议由 Home Assistant 统一设备实体与状态，Phone Agent 通过受限网关调用。HomeKit Device 导入原生 HomeKit 配件，HomeKit Bridge 将 HA 实体导出给 Apple Home；传统 HAP 与 Matter 的多管理员能力须分别处理。已有家庭自动化不自动迁移，也不承诺一键读取用户整个 Apple Home。[S17][S18][S19]

米家路线先围绕用户自有 HA 做个人验证。支持能力由设备型号、账号地区、固件和网关决定，普通蓝牙／红外等并非官方集成全覆盖。当前小米集成许可限定非商业 HA 使用，不等于通用 App SDK；分发方案需单独确认。Apple HomeKit API 数据的用途和跨设备流转也有明确约束。[S20][S21][S26]

首版不将 iOS HomeKit API／数据库导出到通用云端记忆或 Android。家庭状态来自用户在 HA 中直接接入的设备，并保留来源；HomeKit API 获得的数据另设用途与存储边界。

### 最小闭环

选择一盏灯、一个新风或风扇、一个环境传感器。每个实体登记控制路径、状态路径、可读写字段、单位、允许范围和最近实测。界面分别展示已发出、等待反馈、设备已回报、部分完成、待核实与不可用。

控制使用明确目标状态，不把 toggle 作为可重试操作。连接恢复时不补发过期命令。多设备场景允许部分成功，不能用一句“完成”遮住失败实体。新风控制本身也要验证具体设备及其安全条件，不由插座电源状态推断实际运行。

### 默认范围

低风险灯光与有限通风可在当前明确请求下执行；可逆批量场景展示目标后一次确认。门锁、燃气、加热、安防解除不进入首版工具允许清单。新增自动化先审阅规则，再存入 HA 的确定性执行层，避免手机被拿走后规则消失。

## 11 生产力与 App 扩展

一个任务有独立目标、工作区、输入证据范围、执行主机、步骤、授权、日志、产物和终态。界面提供继续、补充说明、请求停止／取消、查看变更和打开产物；只有实现了检查点的任务才显示暂停与恢复。任务完成提示保持轻量，实际细节由用户进入页面查看。

DeepSeek Harness 提供任务执行与扩展基础。当前官方 SDK 的超时不代表执行停止，且 run 返回值可能包含同会话插话，因此产品要在其外层拥有 task ID、事件序列和取消协议。每个重要长任务用独立 session／worker 隔离；远程进程终态未知时，显示“停止请求已发出，等待核实”。[S02]

连接已有 App 的优先顺序为官方 API／MCP、系统 Intent／分享／日历，再到明确授权的界面自动化。手机操控会与全屏宠物争夺前台，打开别的 App 时显示感知暂停状态；MVP 不把全 App 操作作为必要条件。SSH 用于连接实际工作目录，不自动向工作机分享日常家庭全部记录。[S04][S48]

## 12 隐私与用户控制

### 起始保留策略

| 数据 | 建议默认值 | 用户可见语义 |
| --- | --- | --- |
| 原始音频 | 30秒易失环，仅在相应模式开启 | 不默认连续写盘 |
| 相机短缓存 | 有界内存，起始上限20MB | 暂停或离开模式即清理 |
| 自动选择的媒体证据 | 24小时 | 可收藏延长；到期后不再回看原图／音频 |
| 明确要求记住的媒体 | 7天，可选择更久 | 与文本记忆分别显示到期时间 |
| 事件摘要与放置历史 | 30天 | 已过期源证据会标注，不能伪造回放 |
| 确认偏好 | 直到用户修改／删除 | 90天标记待复核，不静默变成永久真相 |
| 工作记录 | 任务结束后30天 | 产物与工作区自身保留策略独立 |

这些是初始配置。原始媒体自动到期与用户主动删除是不同事件：经独立授权保留的摘要可以在源到期后留下，但必须显示“原始证据已过期”；用户要求删除某段及衍生内容时，则执行级联删除。备份恢复前重放删除墓碑，防止已删记忆复活。

### 可见控制

相机、麦克风、背景事件整理、原始证据留存、云端模型调用分别开关。指示器来自真实采集回调，不只跟随 UI 状态。隐私暂停时更新 privacy_epoch，停止新帧与新音频，并使旧采集代际尚未完成的派生作业失去持久写入权限；外部已接收的数据处理情况另行呈现。已授权的工作任务可按其独立权限继续，但不再取得新的环境输入。P0 删除即覆盖源引用、摘要、检索索引、缓存和当前任务 context pack，并阻断迟到结果复活；无法清理的自动持久副本路径暂不启用。

默认不把访客自动标为主人，不从人脸／声音推断敏感个人属性。家庭共享设备需要可见的使用提示和访客模式。任何环境内容，包括纸条、电视、网页、检索记忆，都不能赋予新的设备或工作区权限。

## 13 性能与异常体验

| 项目 | 初始验收目标 | 测量起止与降级 |
| --- | --- | --- |
| 唤醒反馈 | p95 ≤300ms | 检出唤醒到眼睛／字幕变化 |
| 语音打断 | p95 ≤200ms | 本地VAD命中到TTS停止播放 |
| 本地停止 | 软件派发 p95 ≤100ms | 点击到原生层提交stop；机械停止另测 |
| 简单家居 | LAN回读 p95 ≤2s | 有效请求到符合目标的新状态；云设备单列 |
| 记忆检索 | p95 ≤1.5s | 请求到有来源的候选结果，不含完整TTS |
| 首句语音 | p95 ≤2.5s 起始目标 | 用户说完到首段可听回复，复杂任务先短确认 |
| 持续使用 | 先2小时，再8小时 | 记录热状态、掉帧、丢音、断连和实际存活 |

上述指标均不是实测。达不到时先保住语音、停止和状态可信：减少视觉推理与动画、暂停主动转向、降低保存频率，而非持续重启服务。来电、系统权限撤销、相机被占、工作主机休眠、HA 重启都必须有明确的可用能力与恢复路径。

## 14 发布门槛与实施路线

### G0 硬件与平台验证

在实际小米 Android 16 同时运行相机、麦克风、TTS、BLE 和宠物动画。记录2小时完整 trace，并验证拿起、来电、锁屏、断网、进程被杀和供电变化。LOOI 先在固定机身、轮子悬空的夹具上验证停止、断连与进程死亡行为，再进入受保护测试区做带电机的集成故障测试。头部俯仰单独验证限位与停止；任一执行器未通过便禁用该执行器。没有证据证明失联会停，就不开放自主轮式动作。

### G1 单个可演示闭环

接通明确语音＋画面记忆、来源回看与删除；一盏真实灯的设置和回读；一项 Hub DSH 工作任务及产物。引入统一 action receipt 与 task ID。可以让宠物真正完成一次现实到数字的任务，而不是只有几个彼此独立的 demo。

### G2 私人日用 Alpha

加入事件门控、增量记忆、有限主动观察、任务恢复、有限家居自动化和权限设置。先做影子观察再启用主动提示，连续7天记录价值、误记与打扰。本套48条固定回归场景覆盖否定、过期、错人、断线、删除与撤权；错误归属与误报成功不得用平均指标掩盖。

### G3 扩展与分发

在明确目标 SDK、第三方许可和兼容设备范围后，再决定商业发行、iOS、本机 Harness 与更多 App 操控。许可审阅是对具体分发和数据流的决策门槛；私人原型跑通不自动证明可以按同一路线对外提供。

| 阶段 | 工作内容 | 建议工期 |
| --- | --- | --- |
| 第1到2周 | G0与版本／设备清单；基础UI可试用 | 2周 |
| 第3到5周 | G1；任务与记忆权威数据层 | 3周 |
| 第6到9周 | 连续上下文、俯仰主动观察、家居与任务恢复 | 4周 |
| 第10到12周 | G2；真实日用、性能和错误处理 | 3周 |
| 额外缓冲 | 已有能力的音频、OEM、配对与兼容问题 | 2到4周 |

这是基于已有代码、一个主要工程师及阶段性设计支持，对单一设备组合私人 alpha 的12到16周规划估计，G0 后须重估。固件 watchdog 缺失或上游许可授权属于外部阻塞，不能承诺缓冲期内解决。若身体 G0 失败，使用固定机位，由用户手动移动手机或物体来补充视角；若没有常开主机，限定电脑在线时可执行重任务。

## 15 交付与下一次决策

本套交付包含产品需求、15个 UI 状态与交互规范、技术研究与来源、接口草案、评测用例和可重现设计原稿。实现优先级明确：原生停止与生命周期、证据与删除、Home 与 Task 两条可回读执行链，然后扩大背景感知。

开工前需要收集的只有能改变选型的实物信息：底座固件与失联行为、手机与充电温度、家庭设备型号／地区、常开主机、是否计划公开或商业分发。其余产品行为可按本文先构建原型，不需要为每个常规实现选择停下来等待。
