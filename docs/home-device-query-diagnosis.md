## 原因与职责

1. **工具契约不明确。** `apps/nsh/runtime/tools/home-tools.ts:25` 只说明查询设备和状态；`query` 参数没有描述连续子串匹配规则。模型提交了自行拼接的中英文关键词。
2. **实现按整段字符串匹配。** `packages/home-assistant/src/core/voice-tools.ts:28` 将查询转小写、去除首尾空格；第 30 行将名称、房间、设备名和实体 ID 拼接后执行 `.includes(query)`。不会拆词，也不会将 `hall`、`lamp` 映射为中文。实际设备信息不包含 `hall 台灯 lamp`。
3. **空结果后的解释与后续查询不足。** 第 40 行回执提示将“尚未连接”和“未找到”混写；首次模型拿到 0 条结果后，没有改用原始中文关键词再次只读查询。`HomeRuntime.list` 在已有连接 owner 的分支返回本次结果与连接 ID，参见 `apps/nsh/runtime/home.ts:1260`。

这些记录能确认两次模型生成的查询不同；无法据此将查询变化归因于第二次指令中的某个具体词句。

## 建议修正

优先在现有工具描述和参数中明确使用原始设备名或房间关键词，避免自行翻译后拼成一段查询；首次无匹配时扩大只读检索，再根据返回的 `room` 和设备名选择目标。回执分别表达连接失败与查询无匹配。

这项修正可复用现有查询、房间字段和执行记录，不需要新增依赖或检索服务。仅按空格拆分后要求所有词匹配，仍会被不存在的 `hall`、`lamp` 阻断，不能独立解决本次问题。
