# 路由返回与切换性能

测试环境为 iPhone 16e 模拟器、iOS 26.3、NSH 开发宿主，框架固定为 `e626a8d`。通过 `--trace --fps` 记录引擎提交耗时，并在语音入口临时计时；探针未保留在业务代码中。原始数值见 [采样记录](artifacts/navigation-performance.json)。

| 路径 | 修改前单次提交 | 修改后单次提交 |
| --- | ---: | ---: |
| 首次进入管理空间 | 265.6ms | 25.9ms |
| 进入语音页 | 990.6ms | 5.2ms |
| 再次进入管理空间 | — | 16.6ms |
| 返回桌宠首页 | — | 2.5ms |
| 家居详情返回设备列表 | — | 6.7ms |

表中是引擎处理输入并生成原生视图更新的时间，取自对应交互的一次提交；160ms 视觉过渡由原生动画线程播放。它与网络加载完成时间分别计量。

## 原因与实现

`activeSpace` 的变化会同步触发语音待机生命周期。原来的 `setCaptureMode("kws")` 在同一调用中加载唤醒模型、创建音频设备；模拟器测得启动 875–888ms，停止 149–157ms。页面销毁、重新创建，以及 `llm()` 每次读取都遍历整个目录做翻译，进一步增加切换开销。

- 原生 `beginWake()` 同步预留请求代次，`startWake(ticket)` 在线程池加载模型，加载前后核对同一代次。退出页面、关闭唤醒或关闭运行时会使旧请求失效。
- KWS 工作线程收到停止信号后自行退出并释放模型。它只持有旧会话缓冲区，停止入口不再等待线程退出。
- iOS 先同步停止播放器、录音引擎并移除 tap、observer，再后台停用系统会话、还原原始类别。下次启动先等待旧还原任务，避免旧配置覆盖新会话。后台线程只接收字符串和数值，不传递 Objective-C 对象。[Apple 音频会话接口](https://developer.apple.com/documentation/avfaudio/avaudiosession/setactive(_:options:))。
- `localizedLlm` 由目录快照和当前语言共同驱动，一个快照只翻译一次；页面继续使用原来的 `store.llm()` 接口。
- `RetainedPage` 首次访问时创建页面，以后隐藏保留输入和滚动位置。代价是已访问管理页的视图继续占用内存；它免去了常用路由反复重建。底座离页停止控制，隐藏底座页销毁不干预其它来源发起的运动；桌宠隐藏时停止自身动画计时器。
- 页面进入使用 160ms、8pt 的原生淡入位移，遵循系统减少动态效果。重复点击当前一级路由不再重复请求，家居进入刷新由现有可见性 effect 统一持有。

## 验证证据

- NSH 测试：31/31，包含分层返回、路由输入保留、摄像头节点生命周期和 72 表情绘制。语音、模型列表、家居开关/摄像头及构建环境的 Node 用例通过。
- `pnpm --filter @super-looi/nsh typecheck`、`build`：通过。
- `pnpm --filter @super-looi/nsh test:wake:ios`：1/1，覆盖同一轮事件中启动后立即取消、正常 KWS、切换实时采集、复用和停止。
- 路由草稿保留测试覆盖 390×844 与 844×390，并在后一组开启减少动态效果；修改目录共享计算后，草稿测试和语言/外观持久化测试分别通过。
- 模拟器点击六个管理入口、首页往返、家居设备详情返回；测试用离线设备源已恢复为停用。
- 独立 review 核对了异步请求首次执行前取消、隐藏底座页停止副作用、iOS 会话还原顺序，并复核修正。

## 返回层级与隐藏绘制

App 根组件将系统返回注册到 `store.goBack()`，右上角返回使用同一入口：设备详情回设备列表，服务绑定取消进行中的登录并回设备列表，一级管理页回桌宠首页。首页返回 `false`，继续由系统处理；左上桌宠按钮始终直接回首页。无需维护第二份路由历史或新增导航依赖。

`RobotFace` 用页面是否可见的 computed 值统一控制呼吸、动画计时和 Canvas 绘制。隐藏时绘制绑定不再读取逐帧状态，重新显示时重新绘制当前表情。模拟器验证了管理页往返后的完整画布恢复。

分层返回用真实 App 的界面测试覆盖：原实现从服务绑定直接跳回首页，用例失败；修复后界面返回与 `app.back()` 均逐层返回。保留页面的行为测试继续覆盖竖屏、横屏和减少动态效果。
